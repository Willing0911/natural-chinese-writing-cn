# 写作 Skill 校准与迭代

用于把“我觉得差点意思”变成可复用的规则。校准的核心证据是同一任务的「Agent 草稿—人工定稿」差异，单纯让 Agent 总结几篇成文只能作为起点。

## 准备材料

- 2–3 份用户认可的代表作，尽量覆盖主要交付场景；
- 用户明确写过的方法、禁区、受众与发布要求；
- 一个真实的新任务，包含素材、目标、主要观点和交付载体；
- 一个未参与规则提炼的留出样例，用于检查是否过拟合。

代表作必须是用户真正认可的版本。高阅读量、已发布或写得工整都不等于它能代表当前声音。

## 校准回路

### 1. 建立基线

用当前 Skill 完成新任务，保留原始草稿。给定足够具体的目标与材料，不用故意模糊的提示测试 Skill 能否猜中。

### 2. 获得人工定稿

请用户直接改稿、重写或明确接受与拒绝的段落。保留真实修改轨迹，不先向用户解释预设的问题，避免把修改引向既定答案。

### 3. 比较选择，不只比较字词

按六层记录差异：

1. 中心判断：删了哪些安全但空泛的观点，新增了什么选择或取舍；
2. 事实与边界：哪些细节被删除、降级或补证；
3. 信息顺序：什么被前置、合并、拆分或删除；
4. 主线与证据：案例为什么保留，它如何回到当前判断；
5. 声音与姿态：用户如何表达确定、怀疑、关心、批评与不确定；
6. 节奏与表面：句长、段长、转场、标点、标题、表格和列表如何变化。

### 4. 把重复差异写成规则

一次修改先记为假设，两次以上且能说清读者影响时，再升级为规则。每条规则包含：

- 适用场景；
- 要做的选择；
- 读者层面的原因；
- 一个精简的前后对比；
- 一个不适用的反例或边界。

优先写“何时怎么做”，少写绝对禁令。错别字、偶然口语、当天情绪和一次性排版不应直接固化成风格。

### 5. 重复并停止

用更新后的 Skill 再做新任务，重复「生成—人工改写—差异分析—规则更新」。默认 3–4 轮或连续两轮无高价值新差异时停止。

轮数多不代表更准。如果规则开始强制每篇文章出现相同开头、句式、情绪或结尾，视为过拟合信号。

### 6. 用留出样例验收

不带已知定稿做留出任务，检查：

- 事实和交付目标是否完整；
- 声音是否接近用户，又没有复制已知文章的表面特征；
- 新题材下是否仍能自然选择结构；
- 语体切换后，个人长文规则是否污染报告、学生材料或视频脚本。

## 差异记录模板

```markdown
## 校准样例

- 任务与读者：
- 核心观点：
- 交付载体：
- Agent 草稿：
- 人工定稿：
- 高价值差异：
- 规则假设：
- 适用范围：
- 反例或边界：
- 留出任务结果：
```
